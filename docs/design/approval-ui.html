Approval UI — Design Artifact

Every surface involved in tool-call approval: the composer's Manual/Auto toggle, the inline approval panel (pending / queued / denied), the resulting chat note when a call is skipped, and the per-tool Settings switches that back it all. Colors, spacing, and type match the shipping "Ledger" light theme 1:1.

1. Composer Manual / Auto toggle composer-auto-btn

A single pill button that flips every known tool's auto-approve flag at once. Always reads the live policy before toggling (not cached component state) so it can't silently re-enable everything if Settings changed the per-tool switches since the button last rendered.

2. Inline approval panel .approval-panel

Docked directly above the composer as a bordered card matching its own shape/shadow — not a full-screen modal. Non-blocking: switching sessions/tabs stays possible while a request from another session waits underneath.

Notes
  • Tool icon + name reused from the existing timeline row treatment (read/write/edit/bash icon set) so it reads as the same "action" language as the transcript.
  • <pre> input block truncates at max-height: 120px with scroll, matching timeline detail panels.
  • Queue hint appears only when >1 request is pending for this session — cross-session requests stay queued invisibly until you switch tabs.

3. Denied — chat note & composer state chat-line.is-error

Clicking Skip does two things: the SDK's tool_call hook returns { block: true, terminate: true } (stop the turn, don't let the model route around the denial), and the main process emits a distinct chat note so the user gets visible confirmation instead of just a stall.

After clicking Skip
Delete the old backup folder
"bash" was denied — stopping this turn.
Message the agent…
Behavior
  • Reuses the existing error chat-event styling (monospace, danger red) rather than introducing a new visual language for "denial" — it's still an interruption, just a deliberate one.
  • The same event immediately clears busy/thinking client-side, so the composer re-enables at once instead of waiting on the model's (possibly empty) post-termination response.

4. Settings — per-tool approval switches .settings-row

The source of truth the composer button reads/writes in bulk. Read-only tools default to auto-approved; anything that mutates the filesystem or shells out defaults to requiring approval.

Tool approval policy
read Read a file's contents
grep Search file contents
bash Run a shell command
write Create a new file
edit Modify an existing file
